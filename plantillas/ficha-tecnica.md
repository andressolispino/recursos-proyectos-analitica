# Ficha técnica del proyecto

La ficha técnica es **opcional**: resume tu proyecto en una página y te sirve como guion para preparar la sustentación. Si decides usarla, agrégala como **Anexo A** de tu documento final (Hito 3). Copia esta tabla y llena cada fila con los datos de tu repositorio; no inventes ni redondees a mano: todas las cifras salen de `results/tables`.

| Título del proyecto |  |
| --- | --- |
| Integrantes | Nombres completos |
| Pregunta de investigación | Una sola pregunta, tal como quedó en el documento |
| Datos | Fuente y enlace · licencia o autorización · periodo cubierto · número de registros y de variables · variable objetivo |
| Enfoque y tipo de problema | Predictivo o descriptivo · clasificación, regresión, series de tiempo u otro |
| Protocolo de evaluación | Métrica principal · validación (por ejemplo, 5×2 repetida o TimeSeriesSplit) · línea base |
| Modelos comparados | Lista de los modelos de la batería (o KPIs y dashboard, si tu enfoque es descriptivo) |
| Mejor resultado | Mejor modelo · métrica principal con intervalo de confianza del 95 % · mejora frente a la línea base |
| Prueba estadística | Prueba usada · estadístico · valor p · qué se concluye |
| Variables más influyentes | Las 3 principales según SHAP y qué significan en el problema |
| Hallazgo principal | Dos o tres líneas en el lenguaje del problema: qué se puede decidir con tus resultados |
| Limitaciones | Las dos o tres más importantes |
| Enlaces | Colab · GitHub (versión v1.0) · despliegue, si existe · DOI de Zenodo, si lo tienes (opcional) |

Extensión: máximo una página. Si tu proyecto es descriptivo, en «Mejor resultado» reporta los KPIs principales con su comparación y en «Variables más influyentes», los factores que explican las diferencias.
